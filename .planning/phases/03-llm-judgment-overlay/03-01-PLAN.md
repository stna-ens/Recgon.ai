## Phase Goal (plain English)

When two or three teammates are nearly tied for a task, Recgon-the-AI-PM asks an AI judge to pick the best fit and write a one-sentence reason. This plan builds the **judge itself** as a standalone, well-tested module — no dispatcher wiring, no database changes yet. Think of it as building the engine on a workbench before putting it in the car.

<objective>
Ship a pure `runJudgment` function (in `src/lib/recgon/judge.ts`) that:
1. Takes a batch of close-call tasks + their anonymized top-3 candidates.
2. Calls `chatViaChain` (or an injected stub for tests) at `temperature: 0` with the JUDGE_ASSIGNMENT_BATCH prompt.
3. Validates the response with `JudgeResultSchema` (Zod) AND a post-hoc content validator (chosen_id ∈ {1,2,3}, sentence cites a real payload signal, no names/pronouns).
4. Throws on any failure so the caller can do math-only fallback.
5. Exposes a deterministic cache-key helper for Plan 02 to consume.

Purpose: build the judgment engine in isolation so Plan 02 (dispatcher integration) and Plan 04 (bias regression) can wire it in with confidence.
Output: `judge.ts` module, prompt, schema, types, full unit-test coverage, and the 5 bias-fixture JSON files (consumed by Plan 04 but cheap to create now).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `runJudgment` ← prompt input | Task title/skills/recent-tasks come from `agent_tasks` (Recgon-minted). Skill vocab is canonical (Phase 2 D-23). Risk surface: anything user-typed that leaks into the title field. |
| `runJudgment` → `chatViaChain` | Outbound LLM call. Risk: prompt injection from any unsanitized field. |
| `chatViaChain` → `runJudgment` | LLM response. Risk: hallucinated reasoning, name leaks, schema violations. |
