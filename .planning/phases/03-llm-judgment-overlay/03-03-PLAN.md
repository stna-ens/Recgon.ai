## Phase Goal (plain English)

When Recgon assigns a task, the assignee gets a one-line explanation in their assignment email and in the task pop-up: "**Why you:** recent track record — you finished 3 similar React tasks in the last two weeks." Owners can see every teammate's "Why you" line; other teammates see nothing (it's private like fit scores). Math-only assignments also get a "Why you" line, generated from the math breakdown, so no assignment is ever a black box.

<objective>
1. Add `assignment_reasoning JSONB` column to `agent_tasks` (additive migration, default null — backwards compatible).
2. **[BLOCKING]** Push the migration to the live DB before any code writes to it.
3. Extend `assignTask` to write the `reasoning` arg (which Plan 02 already passes through).
4. Build `src/lib/recgon/whyYou.ts` — the single source of truth for "Why you" copy, with one template per `reason_code` plus a math-only fallback template.
5. Wire `renderWhyYou` into the assignment email (`notifyTeammateAssigned`) and `TaskDetailPanel.tsx`.
6. Server-side privacy: the API route that hydrates `TaskDetailPanel` strips `assignment_reasoning.whyYouSentence` for anyone who is NOT the assignee or the team owner.
</objective>

<interfaces>
NEW renderer in `src/lib/recgon/whyYou.ts`:
```typescript
export type WhyYouOutput = {
  headerLabel: string;        // always "WHY YOU" (locale-stable for now)
  sentence: string;           // the one-line explanation, ≤ 120 chars rendered, ≤ 25 words
  confidenceClass: 'low' | 'medium' | 'high' | 'na';  // 'na' for math-only
};

export function renderWhyYou(reasoning: AssignmentReasoning): WhyYouOutput;
```

Reason-code template table (all in Recgon-AI-PM voice — see CONTEXT D-29):

| reason_code | template (parameterized) |
|-------------|--------------------------|
| `recent_track_record` | "Recent track record — {reason_sentence}" |
| `interest_match` | "Interest match — {reason_sentence}" |
| `skill_depth` | "Skill depth — {reason_sentence}" |
| `task_kind_familiarity` | "Familiar work — {reason_sentence}" |
| `capacity_headroom` | "Clearest week — {reason_sentence}" |
| `math_only` (kind === 'math_only') | "Your fit score was strongest among teammates available this week ({skillBand}/{availabilityBand})." |

Note: for non-`math_only` cases, the `reason_sentence` is taken VERBATIM from the LLM (already post-validated in Plan 01). The renderer prepends the human label; it never paraphrases the sentence. If `reason_sentence` is somehow empty/null (defense in depth), fall back to the math-only template using the embedded `mathBreakdown`.
</interfaces>

NEW privacy contract in `src/app/api/recgon/tasks/[id]/route.ts`:
- GET returns the task row.
- If `reasoning != null`, check session:
  - `session.userId === task.assignee_id` → include `whyYouSentence` (the rendered string from `renderWhyYou`)
  - `session.role === 'owner'` on the task's team → include `whyYouSentence`
  - else → strip `whyYouSentence` entirely (other teammates can see the task but not its reason)
- Raw `reasoning` JSONB is NEVER returned to the client (only the rendered sentence). This prevents prompt-injection-by-reflection if the LLM somehow produced HTML inside a sentence.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `agent_tasks.assignment_reasoning` ← `assignTask` | Service-role write surface. |
| `/api/recgon/tasks/[id]` → client | Network boundary, response payload reaches browsers. |
| `notifyTeammateAssigned` email → recipient inbox | Outbound boundary; reasoning sentence leaves the app. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Tampering | `assignment_reasoning` JSONB writes | mitigate | Service-role-only writes (`storage.ts` uses the service-role Supabase client per CLAUDE.md). Zod `AssignmentReasoningSchema` validates the shape before every write — on parse failure, write `null` (NOT the bad payload). |
| T-03-03-02 | Information Disclosure | `whyYouSentence` exposure via API | mitigate | Server-side check in `route.ts`: assignee OR owner only. Other teammates get the field stripped. Test in `assignmentReasoning.privacy.test.ts` covers all 3 viewer types. |
| T-03-03-03 | Information Disclosure | Raw `assignment_reasoning` JSONB reaching the client | mitigate | API NEVER returns the raw column — only the pre-rendered `whyYouSentence` string. Defense against future schema changes accidentally leaking richer data (math scores, candidate user_ids, judge confidence). |
| T-03-03-04 | Tampering | HTML/script injection via `reason_sentence` in the email or DOM | mitigate | `renderWhyYou` strips `<` and `>` defensively. React's default JSX rendering in `TaskDetailPanel` escapes the string. Email template uses a plain-text fallback alongside HTML — React Email auto-escapes string interpolation. |
| T-03-03-05 | Repudiation | No audit of who saw the "Why you" line | accept | Phase 3 doesn't add view-tracking. Existing API request logs cover access pattern if forensics ever needed. |
| T-03-03-06 | Spoofing | A teammate fakes assignee identity via session manipulation | mitigate | `route.ts` checks `session.userId` server-side — same trust model as every other Recgon API route. No new attack surface. |
</threat_model>
