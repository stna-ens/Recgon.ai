# Phase 1 — UI Design Contract

> Visual and interaction contract for the `/teams/[id]/me` profile page. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Inherits the existing Recgon design language (Apple Wabi / liquid glass / signature pink) — no new aesthetics introduced. Per D-22, this page MUST feel native to today's app.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (existing in-house token system in `src/app/globals.css`) |
| Preset | not applicable — shadcn intentionally NOT initialized; D-22 mandates inheritance of existing `.glass-card` / liquid glass tokens, not introduction of a parallel design system |
| Component library | `@radix-ui/themes` (`Box`, `Flex`, `Text`) + Radix primitives (`@radix-ui/react-popover`, `@radix-ui/react-label`, `@radix-ui/react-tooltip`) + `cmdk` for the suggestion picker |
| Icon library | `lucide-react` (already in deps) |
| Font | Inter (body 300/400/500/600/700), JetBrains Mono (labels + metadata + `matched as:` annotations 400/500) |

**Rationale (D-22 / D-23):** No `components.json` exists and none will be added in Phase 1. shadcn-style hand-rolled wrappers around the existing CSS tokens are acceptable in `src/components/ui/*` ONLY if they consume `var(--glass-substrate)`, `var(--signature)`, `var(--r-md)`, etc. — never their own palette.

## Spacing Scale

Declared values (all multiples of 4, sourced from existing CSS rhythm):

| Token | Value | Usage on this page |
|-------|-------|--------------------|
| xs | 4px | Inline pill icon gap, label-to-help-text |
| sm | 8px | Gap between pills in a chip-row; suggestion-popover item padding-y |
| md | 16px | Form field internal padding; label-to-input gap |
| lg | 24px | Gap between form fields (skills → strengths → interests → capacity) |
| xl | 32px | Page-edge padding on the glass-card; section-to-section gap (form ↔ disabled GitHub placeholder) |
| 2xl | 48px | Page-top padding below the top-nav dock; gap between the page heading and the form card |
| 3xl | 64px | Reserved — not used on this page |

**Border radii (mapped to existing tokens, NOT spacing):** `--r-sm: 14px` for pill chips, `--r-md: 24px` for the form card surface, `--r-pill: 999px` for the suggestion-popover wrapper.

**Exceptions:** Touch target on the pill chip's remove (×) button is 32×32px hit-area with an 8px visual circle inside — meets the 32px minimum without inflating the visual pill height beyond the 28px design.

## Typography

Three sizes + one display variant. Two weights only. **Exactly 4 sizes declared — no exceptions.**

| Role | Size | Weight | Line Height | Font | Where it lives |
|------|------|--------|-------------|------|----------------|
| Display | 28px | 600 | 1.2 | Inter | Page heading: "Your profile" |
| Heading | 20px | 600 | 1.3 | Inter | Section heading inside form card; disabled placeholder heading |
| Body | 16px | 400 | 1.5 | Inter | Form field input text, helper copy, pill chip raw text |
| Label | 12px | 500 | 1.4 | JetBrains Mono, letter-spacing 0.04em, uppercase | Field labels (`SKILLS`, `STRENGTHS`, `INTERESTS`, `WEEKLY CAPACITY`); `CANONICAL` / `OTHERS` suggestion-popover badges; "COMING SOON" badge; capacity suffix |
| Label (annotation variant) | 12px | 400 | 1.4 | JetBrains Mono | `matched as canonical` pill annotation — **same 12px size as the Label role**, distinguished by weight 400 (vs 500), normal case (vs uppercase), and `var(--txt-faint)` color (vs `var(--txt-pure)`) |

**Strict weight palette:** 400 (regular body) + 600 (heading / button / emphasis). The Inter `500` weight already loaded in `globals.css` is reserved for the JetBrains Mono label role above and the nav-link label — DO NOT introduce 500-weight Inter on this page.

**`matched as:` annotation rendering (resolves CONTEXT discretion item):** Render inline, **immediately below the pill chip raw text**, in **JetBrains Mono 12px / weight 400 / `color: var(--txt-faint)`**, prefixed with the literal text `matched as `. The pill becomes a two-line chip: raw on line 1, `matched as backend` on line 2.

  - **Why 12px (not a 5th size):** The annotation MUST stay within the 4-size budget. Visual hierarchy between the Label role (`SKILLS` uppercase, 500 weight, `--txt-pure`) and the annotation variant (`matched as backend`, 400 weight, normal case, `--txt-faint`) is carried by **color and font-family**, not size. Both are 12px JetBrains Mono.
  - **Justification over the tooltip and the "Recgon sees these as:" footer alternatives:**
    - Always-visible (D-14 explicitly requires the teammate to see how Recgon read them — a hover tooltip hides it for keyboard users and mobile; a separate footer creates two parallel lists the teammate has to mentally zip together).
    - Survives the disabled / read-only render needed for cross-teammate viewing when `profile_visibility = team_visible`.
    - Scales to the 6–12 pill case (a footer line would wrap unreadably; tooltips are one-at-a-time).
  - **Empty edge case:** if normalization returns no canonical match for a raw entry (rare — the strict-filter against `skillVocabulary.ts` dropped everything), render `matched as —` in the same slot. Never hide the line; the consistent two-line height prevents layout shift after save.

## Color

Inherits the existing two-mode token system. The page MUST work in both `:root` (light) and `.dark` without ever hardcoding hex.

| Role | Value | Usage on this page |
|------|-------|--------------------|
| Dominant (60%) | `var(--bg-deep)` (light `#f5f5f7` / dark `#000000`) | Page background — extends behind the form card; ambient mesh-bg already painted by `AppShell` |
| Secondary (30%) | `var(--glass-substrate)` (light `rgba(255,255,255,0.75)` / dark `rgba(20,20,22,0.6)`) — applied via the existing `.glass-card` rule | Form card surface; disabled GitHub placeholder card; suggestion popover surface |
| Accent (10%) | `var(--signature)` (light `#c2357a` / dark `#f0b8d0`) | **Reserved-for list below — exhaustive** |
| Destructive | `var(--danger)` (light `#FF3B30` / dark `#FF453A`) | Save-failure toast; per-field error border + helper text |

**Accent reserved for (exhaustive — anything not on this list MUST NOT receive signature pink):**

1. The primary CTA button background ("Save profile") — solid `var(--signature)` fill with white text in both modes.
2. The active state of a focused form input — 1px border `rgba(var(--signature-rgb), 0.6)` + 0 0 0 3px `rgba(var(--signature-rgb), 0.15)` focus ring.
3. The selected suggestion item in the cmdk popover — left 2px border in `var(--signature)`.
4. The "Your profile" page heading underline (1px line in `rgba(var(--signature-rgb), 0.4)`, 64px wide, sits between heading and form).
5. The success-state toast accent ("Profile saved — Recgon will use this on the next run") — left 3px border in `var(--signature)`.

**Pill chips do NOT receive accent.** Pills use `--btn-secondary-bg` background + `--btn-secondary-border` border. This is critical: a teammate may have 8–12 pills, and painting them pink would violate the 10% rule and visually compete with the Save CTA.

**Disabled placeholder does NOT receive accent.** Greyed entirely (see Section: Disabled placeholder treatment).

## Copywriting Contract

Voice rule (D-21): Recgon IS the AI PM. Copy speaks AS Recgon — never about an AI feature. NO "Powered by AI", NO "the AI thinks", NO robot emojis, NO "Let our AI…", NO machine-learning jargon. Tone = a smart manager onboarding a new teammate.

| Element | Copy |
|---------|------|
| Page heading | `Your profile` |
| Page sub-copy (one line, body 16px, `--txt-muted`) | `What you tell me here is what I'll use to assign you tasks.` |
| Skills field label | `SKILLS` |
| Skills field helper | `Languages, frameworks, areas of expertise. Type and pick from suggestions, or add your own.` |
| Skills input placeholder | `e.g. PostgreSQL, React, copywriting…` |
| Strengths field label | `STRENGTHS` |
| Strengths field helper | `What you're known for on a team. Counts the same as skills when I'm matching tasks.` |
| Strengths input placeholder | `e.g. shipping fast, debugging hard bugs…` |
| Interests field label | `INTERESTS` |
| Interests field helper | `What you'd lean into given the choice. I'll use this to break ties when two of you fit a task equally well.` |
| Interests input placeholder | `e.g. design systems, growth experiments…` |
| Capacity field label | `WEEKLY CAPACITY` |
| Capacity field suffix | `hours / week` |
| Capacity field helper | `How much time you have for new work in a typical week.` |
| Primary CTA | `Save profile` |
| Primary CTA — saving state | `Saving…` (button disabled, button text replaced; left-side 14px lucide `Loader2` icon, `animation: spin 0.8s linear infinite`) |
| Primary CTA — success state (transient ~1.5s after save) | `Saved` with `Check` icon, then reverts to `Save profile` |
| Empty state heading (when the page first loads and the teammate has no profile row) | `Let's get this set up.` |
| Empty state body | `I don't have anything from you yet. Fill in what fits — you can change any of it later.` |
| Error state (LLM call fails AFTER dual-provider chain exhausts) | `I'll save what you typed and match it next time. Anything wrong with how I read these? Edit and save again.` (toast, info severity — NOT destructive red; this is the raw-text fallback per RESEARCH.md, the data IS saved) |
| Error state (validation — empty raw text on submit) | `Add at least one skill before saving.` (inline below the skills field, `var(--danger)`) |
| Error state (validation — capacity out of range 0–80) | `Capacity should be between 0 and 80 hours.` (inline below capacity field) |
| Error state (network / 5xx — save did NOT persist) | `Couldn't save. Try again in a moment.` (toast, destructive) |
| Destructive confirmation | **Not applicable for Phase 1.** Editing the profile is non-destructive (upsert). The only "destructive" interaction is removing a pill chip, which is immediately reversible by re-typing — no modal confirmation needed. |
| Disabled placeholder heading | `What GitHub will say about you` |
| Disabled placeholder badge | `COMING SOON` |
| Disabled placeholder body | `Once you connect a repo, I'll look at what you actually ship and add it here. You'll get to confirm or reject each one.` |
| Discovery nav link (in team menu, per D-10) | `My profile` |
| Pill chip remove button accessible label | `Remove {chip text}` — e.g. `Remove PostgreSQL`, `Remove shipping fast`. Rendered as `aria-label` on the `<button>` wrapping the `X` icon (icon-only button, no visible text). |

**Strict copy bans on this page (enforced by gsd-ui-checker):**
- The strings `AI`, `Powered by`, `LLM`, `Gemini`, `Claude`, `model`, `algorithm`, `machine learning` MUST NOT appear in any user-facing copy on this page.
- No emoji anywhere on this page (consistent with the rest of the app's restraint).
- No exclamation marks except in the empty-state heading (`Let's get this set up.` — already exclamation-free; the rule confirms no others creep in).
- "Recgon" never appears in third person on this page. The voice is first-person ("I'll use this", "I don't have anything from you yet") OR direct second-person to the teammate ("Your profile", "What you tell me"). Never "Recgon will…".

### Skill picker (cmdk + Radix Popover) — the load-bearing interaction

**Anchor:** A bordered surface using `--btn-secondary-bg` background + `--btn-secondary-border` border + `--r-sm` corners, sitting in place of a traditional `<input>`. The surface contains pills + a trailing free-text input. Click anywhere on the surface focuses the input.

**Input behavior:**
1. As the user types, a `<Popover>` opens below the surface (anchored to the input, NOT the surface — keeps popover stable when pill count changes). Popover surface uses `--glass-substrate` + `--shadow-float` + `--r-md`, max-height 240px, internal scroll via Radix `<ScrollArea>`.
2. Popover content is a `<Command>` from `cmdk` showing ranked suggestions (planner chooses ranking algo — prefix, fuzzy, recent-in-team).
3. **Keyboard contract:** `ArrowDown` / `ArrowUp` navigate, `Enter` commits highlighted suggestion as a pill, `Esc` closes popover (input retains text). `Backspace` on empty input removes the rightmost pill. `,` (comma) or `Enter` on free-typed text the popover doesn't recognize commits it as a raw-only pill (will be normalized server-side on save — D-12).
4. Suggestions show canonical-vocab matches first (badged with a 12px JetBrains Mono `CANONICAL` chip in `--txt-faint` — uses the standard Label role size, not a smaller variant), then free-text matches from other teammates (badged `OTHERS` in `--txt-faint`, same 12px). Max 8 suggestions visible without scrolling.
5. Selected suggestion has a 2px left border in `var(--signature)` and `--glass-active` background — only place in the popover that uses accent.

**Pill chip anatomy:**
- Height: 28px visual / 32px hit-area.
- Background: `--btn-secondary-bg`. Border: 1px `--btn-secondary-border`. Radius: `--r-sm` (14px).
- Padding: 4px 8px 4px 12px (more on left because the X is on the right).
- **Content structure:**
  - Line 1 (raw text): Inter 16px / 400 / `var(--txt-pure)` — uses the Body typography role.
  - Line 2 (annotation): `matched as canonical` in **JetBrains Mono 12px / 400 / `var(--txt-faint)`** — uses the Label (annotation variant) typography role. Same 12px size as the field labels and suggestion badges; distinguished from them by lowercase, weight 400, and `--txt-faint` color.
- **Trailing remove (X) button — accessibility contract:**
  - Visual: 16px lucide `X` icon centered inside a 32×32px hit-area (8px visual circle, 12px transparent padding all around).
  - Color: `--txt-muted` by default, `--danger` on hover.
  - **`aria-label="Remove {chip text}"`** — REQUIRED on the `<button>` element wrapping the icon. The `{chip text}` interpolation uses the raw text shown on line 1 of the pill, NOT the canonical match. Example: a pill displaying `PostgreSQL` → `<button aria-label="Remove PostgreSQL">`. A pill displaying `shipping fast` → `<button aria-label="Remove shipping fast">`. This prevents a WCAG 2.1 SC 1.1.1 failure (non-text content must have a text alternative) since the button has no visible text.
  - The `<X>` lucide icon itself MUST carry `aria-hidden="true"` so screen readers only announce the button's `aria-label`, not "x" twice.
  - Click removes the pill. Pill removal animates opacity 1→0 over `--dur-fast` (0.15s) then collapses width — uses the `--ease-out` token.
- **No accent on pills. No hover scale. No glass treatment on pills** (would violate "no stacked glass" rule, since pills sit inside an already-glassy form card).

**Pre-save state (after user types, before clicking Save):** New pills typed but not yet saved have NO `matched as:` line resolved (server hasn't normalized them). Render line 2 as `matched as …` in **JetBrains Mono 12px / 400 / `var(--txt-faint)`** with the three dots literal — signals "we'll figure this out when you save." After successful save, the page re-renders with the real canonical line (same typography, just replacing the `…` with the canonical token).

### Capacity input

Numeric `<input type="number" inputmode="numeric" min={0} max={80} step={1}>`. Width: 80px. Same border + radius as a pill anchor. Suffix `hours / week` rendered as a sibling `<Text>` in JetBrains Mono 12px / `--txt-muted`, 12px gap to the input's right edge.

### Disabled placeholder treatment (D-09 — non-negotiable)

The "What GitHub will say about you" card sits 32px below the form card. It is a real, rendered card that MUST NOT shift, animate, or react to hover.

- **Surface:** Same `.glass-card` as the form card BUT with `opacity: 0.55`, `pointer-events: none`, `filter: saturate(0.4)`.
- **Content:** Heading + COMING SOON badge + one-line body copy. Nothing else inside. No fake skill rows, no loading skeleton, no placeholder pills — D-09 explicitly forbids fake data.
- **COMING SOON badge:** 22px height, padding 4px 10px, `--r-pill` corners, JetBrains Mono 12px / 500 uppercase letter-spacing 0.08em (Label role), background `--btn-secondary-bg`, color `--txt-muted`, border 1px `--btn-secondary-border`. Sits inline at the right of the heading.
- **Cursor:** Default cursor inherited from `pointer-events: none` (no `not-allowed` — the card is informational, not an attempted interaction).
- **Layout reservation:** Card has a fixed `min-height: 96px` so that Phase 2 lighting it up doesn't push the rest of the page around. This min-height accommodates the heading + badge + one-line body without any extra content.
- **No focus state, no keyboard reachability.** `tabindex="-1"` on the card root.

### Team-menu nav-link entry point (D-10)

In `src/app/teams/[id]/page.tsx` (or whichever team-page nav component renders the team menu), add a single nav link: `My profile`, pointing to `/teams/[id]/me`. Use the existing nav-link styling (the `.nav-link` rule in `globals.css`) — no special treatment, no badge, no count indicator. NO nag banner. NO dashboard summary card. NO first-login redirect. Discovery is silent — owners nudge teammates manually.

### Cross-teammate read view (when `profile_visibility = team_visible`)

If a teammate visits `/teams/[id]/me?user={otherUserId}` (planner decides URL shape — this is the discretionary call from the visibility decision), the same page renders **read-only**:
- All inputs become `disabled` with `cursor: default` and reduced contrast (no border focus glow).
- Pills are non-removable (X button hidden — no `aria-label` needed in this state since the button is not in the DOM).
- Save button hidden entirely.
- A small JetBrains Mono caption above the heading: `VIEWING {Display Name}'S PROFILE` in `--txt-muted`.
- When `profile_visibility = owner_only` AND viewer is not the owner AND not self → 403 server-side, no UI render.
