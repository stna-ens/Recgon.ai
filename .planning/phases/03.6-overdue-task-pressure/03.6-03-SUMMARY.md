# Phase 3.6 / Plan 03 — Overdue Task Pressure: Side Effects (Email + Storage + Snooze)

Wired the pure Plan 02 policy to real side effects: the daily cron now sends nudge / escalation / reschedule emails, writes `teammate_event_log` rows, bumps `agent_tasks.overdue_tier`, and rewrites schedules for Tier 3. Owners get a Snooze N-days escape hatch via a new POST route.

## What landed

**New module — `src/lib/recgon/overdueRunner.ts`** (213 lines)
`executeOverdueAction(task, action, teammate, owner, today?)` is the side-effect dispatcher paired with the Plan 02 `decideOverdueAction()` brain.
- Tier 1 → `sendOverdueNudge` to assignee + `markOverdueAction(taskId, 1, 'nudged', …)`.
- Tier 2 → `sendOverdueEscalation` to owner (NEVER the assignee) + `markOverdueAction(taskId, 2, 'escalated', …)`.
- Tier 3 → `planTaskSchedule()` over a 21-day lookahead with cross-team load aggregation (`loadHoursByDateForUser` for humans, `loadHoursByDateForTeammate` for AI/anon). On capacity: `setTaskSchedule()` with the original date preserved in `schedule_note` ("auto-rescheduled from 2026-05-10 (was 9d overdue) — …"), then `sendAutoReschedulNotice` to the assignee. On no-capacity: `reassignTask(taskId, null, 'recgon')` so the dispatcher picks up the orphan next cycle.
- Same `today` clock flows through the policy AND the email body so day-count drift mid-sweep is impossible.
- Missing emails (no `teammate.userId` / no `users.email` row) skip the send + debug-log; the loop never aborts.

**Updated — `src/lib/recgon/storage.ts`**
- `sweepOverdueTeams(today?)` — replaced Plan 01 stub. Loads teams with `overdue_pressure_enabled=true`, active-status tasks (`assigned/accepted/in_progress/awaiting_review`), `listTeammatesWithStats`, owner via `teams.created_by → users`. Calls `decideOverdueAction` per task, delegates non-`none` to `executeOverdueAction` (via dynamic import to break the runner ↔ storage cycle). Returns `{ teamsProcessed, actionsByKind }`. Try/catch per task so one bad row doesn't kill the sweep.
- `markOverdueAction(taskId, tier, event, context?)` — bumps `overdue_tier` + `last_overdue_action_at=NOW`, writes the matching `teammate_event_log` row with payload `{tier, daysOverdue, previousScheduledDate, newScheduledDate, ownerUserId, handoff}`. Two separate writes (Supabase service-role client has no transaction primitive); both interleavings are safe per the file comment.
- `snoozeTask(taskId, days)` — shifts `scheduled_date` (and `scheduled_until_date` if set) forward by N calendar days, resets `overdue_tier=0`, clears `last_overdue_action_at`, writes a `snoozed` event-log row. Trusts the route layer to validate the 1–30 integer range.

**Updated — `src/lib/email.ts`** — added three Resend wrappers (`sendOverdueNudge`, `sendOverdueEscalation`, `sendAutoReschedulNotice`) that fire-and-forget plain-text emails using the templates in `prompts.ts`. Failures log at `warn` level and resolve; no `RESEND_API_KEY` → debug skip. Mirrors the `notifications.ts` precedent.

**Updated — `src/lib/prompts.ts`** — added `OVERDUE_NUDGE_TEMPLATE`, `OVERDUE_ESCALATE_TEMPLATE`, `OVERDUE_RESCHEDULE_TEMPLATE`. Plain-text body, PM voice, no shame / no false urgency, always offers an out ("request reschedule"). Subjects clamped to 60 chars to fit standard inbox views.

**New route — `src/app/api/teams/[id]/tasks/[taskId]/snooze/route.ts`** (POST)
Owner-only via `verifyTeamAccess`. Body `{ days: number }` with integer 1–30 validation. 403 for non-owners, 404 for wrong team / missing task, 400 for terminal-status tasks or invalid days. Calls `snoozeTask(taskId, days)` and returns `{ ok: true }`.

**Updated — `architecture.md`** — refreshed entries for `/api/cron/overdue-sweep` (real impl, not stub), added the new snooze route, refreshed `lib/recgon/storage.ts` entry, added `lib/recgon/overdueRunner.ts` and `lib/email.ts` entries.

## Key behaviors verified

- **Right recipient per tier:** assignee for Tier 1, owner for Tier 2, assignee again for Tier 3. Asserted by separate `expect(...).toHaveBeenCalled()` / `expect(...).not.toHaveBeenCalled()` per email function.
- **Original schedule preserved in audit trail:** Tier 3 `schedule_note` contains both the original `scheduledDate` AND the overdue-days count.
- **Cool-down idempotency:** pure policy returns `none` on the second pass within 24h, and the caller (sweep loop) skips the runner entirely — so a cron double-tap produces 0 duplicate emails / 0 duplicate event rows.
- **No-capacity fallback:** Tier 3 without a viable `planTaskSchedule()` result returns the task to backlog via `reassignTask(taskId, null)`, leaving the dispatcher to pick it up.
- **Snooze contract:** N-day forward shift, tier reset, cool-down clear, audit event — all verified by direct assertion of the update payload and event-log insert.

## Deviations from plan

- **Scheduler import name:** plan referenced `buildSchedulePlan(task, teammate)`. Actual export is `planTaskSchedule({ teammate, task, loadByDate, now })`. Used the real name; runner builds the `loadByDate` map via existing `loadHoursByDateForUser` (humans) / `loadHoursByDateForTeammate` (AI/anon) before calling the planner. Rule 3 (blocking issue) auto-fixed.
- **Cycle break:** `overdueRunner.ts` imports `markOverdueAction` / `setTaskSchedule` / `reassignTask` / `loadHoursByDate*` from `storage.ts`, and `storage.ts:sweepOverdueTeams` calls back into the runner. Used a dynamic `await import('./overdueRunner')` inside `sweepOverdueTeams` to break the module-evaluation cycle. Rule 3 auto-fixed.
- **Email lookup inline:** Plan suggested re-using a precedent helper from `notifications.ts`. That file imports the whyYou renderer chain (`renderWhyYou` → LLM provider stack), which would pull the entire LLM graph into the cron path. Instead, `overdueRunner.ts` has its own minimal `getEmailForTeammate` using a dynamic `import('../supabase')`. No new behavior, just isolated import surface. Rule 2 auto-fix (correctness — avoid pulling LLM clients into a cron with no LLM calls).
- **`teams` table owner column:** Plan implied a `getTeamOwner(teamId)` helper. Recgon's existing schema uses `teams.created_by` as the canonical owner anchor (no separate helper needed). Inlined the join in `sweepOverdueTeams`. Rule 3.

No CLAUDE.md violations, no security issues, no architectural changes (no new tables, no new env vars).
