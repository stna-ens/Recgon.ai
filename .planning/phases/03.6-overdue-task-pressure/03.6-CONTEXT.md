# Phase 3.6: Overdue Task Pressure — Context

## Problem (today's behavior)

When a task's deadline passes and the task is not in a terminal status, Recgon does **nothing**:

- No status change (no `overdue` enum exists in `TaskStatus`).
- No visual flag — the deadline is printed as plain text on `/tasks` with no warning color or chip.
- No email/nudge to the assignee.
- No notification to the owner.
- No automatic rescheduling or reassignment.

The only existing self-corrections in `dispatcher.ts` are:
1. `backfillLegacySchedules` — fills in `scheduled_date` for assigned tasks that don't have one.
2. Teammate-initiated reschedule requests (Phase 3 reschedule flow).

There is no system pressure pushing overdue work forward. An overdue task is invisible unless a human owner happens to scroll past it. For an "AI Product Manager," this is a glaring gap — the most basic PM job is noticing slipping work.

## Goal

When a task's `scheduled_date` is in the past and its status is not terminal (not `completed` / `declined` / `failed` / `cancelled`), Recgon applies **graduated pressure**:

- **Tier 1 (1–2 days overdue):** private nudge to the assignee via email + in-app banner. No owner involvement yet — respects autonomy.
- **Tier 2 (3–6 days overdue):** escalation to the team owner via email + owner-board badge. Assignee sees that the owner has been notified.
- **Tier 3 (7+ days overdue OR explicit owner action):** automatic reschedule to the assignee's next available working day, using the existing `buildSchedulePlan` scheduler. If capacity is gone, fall back to reassignment via the existing dispatcher path.

**Non-goals (explicit):**
- Not a notification system — graduated pressure means we send the minimum signal at each tier, not a daily ping.
- Not a new task lifecycle status — overdue is a derived property (`scheduled_date < today AND status NOT terminal`), not a stored state. Stored state would require migration coordination with everything that touches status.
- Not punitive — copy + UI affordances treat overdue as "let's get this unstuck," not "you failed."

## Success criteria (what must be TRUE)

1. A task assigned to a teammate with `scheduled_date = 2 days ago` and status `assigned` triggers exactly ONE nudge email to that teammate within 24h of becoming overdue, and exactly ZERO emails to the owner.
2. The same task five days later triggers ONE escalation email to the owner (not a second nudge to the teammate), and the owner-board displays a tier-2 badge on the task row.
3. A task 8 days overdue is auto-rescheduled to the assignee's next available working day; the original `scheduled_date` is preserved in `schedule_note` for audit; an `auto_rescheduled` event lands in `teammate_event_log`.
4. Running the overdue cron twice in the same 24h window produces zero duplicate emails for the same task at the same tier (cool-down enforced via `last_overdue_action_at`).
5. An owner can click "Snooze 3 days" on an overdue task; the cron skips it until the snooze expires (sets a future `scheduled_date`); a `snoozed` event lands in the log.
6. With the overdue feature disabled per-team (feature flag), the system behaves exactly as it does today — purely additive rollout.

## Locked decisions (carry into PLAN-phase)

- **Overdue is derived, not stored.** A task is overdue when `scheduled_date < today() AND status IN active_set`. No new `TaskStatus` value. Storing tier + last action is fine; storing "overdue=true" is not.
- **Cron, not realtime.** Detection runs once per day at a fixed hour via Vercel cron (`/api/cron/overdue-sweep`). Realtime would require listening on task updates everywhere; cron is enough for a daily-pressure feature.
- **Email channel = Resend** (already wired for assignment emails per Phase 4 plan). No new providers.
- **Cool-down = 24h per tier per task.** Same tier can fire only once in 24h. Tier escalation only happens day-by-day — a 7-day-overdue task that was never nudged will go through tiers 1 → 2 → 3 on consecutive sweeps, never skipping.
- **Auto-reschedule reuses `buildSchedulePlan`** from `src/lib/recgon/scheduler.ts` — no new scheduler logic. If `buildSchedulePlan` returns null (no capacity in horizon), fall back to the existing reassign path.
- **Copy bound by `prompts.ts`** — all email/UI copy lives there, same rule as Phase 4. No flattery, no shame, no false urgency.
- **Per-team feature flag** (`teams.overdue_pressure_enabled`, default true). Lets a team opt out if the cadence doesn't fit their workflow.
- **Owner-only escalation visibility.** Tier-2/3 badges show on the owner board only; the assignee sees their own tier-1 banner but not the owner's escalation badge (mirrors Phase 1 D-20 privacy rule).

## Open questions for the planner

1. **Working-day capacity check during auto-reschedule.** Should Tier 3 try the assignee's calendar first (push to their next free day) before falling back to reassignment, or always trigger reassignment? Recommended: try assignee first; only reassign if their next-week capacity is also full.
2. **Tier 2 email frequency.** If a task stays at Tier 2 for 4 days, does the owner get 4 emails or 1? Recommended: 1 (cool-down spans the tier, not 24h, after first send). Planner to confirm.
3. **Test scope.** UAT plan should include a clock-injection helper so cron behavior can be tested deterministically against fixture dates.

- **07-01: Schema + sweep cron.** Migration: add `overdue_tier int default 0`, `last_overdue_action_at timestamptz` to `agent_tasks`; extend `teammate_event_log_event_check` with `nudged`, `escalated`, `auto_rescheduled`, `snoozed`; add `teams.overdue_pressure_enabled boolean default true`. Wire `/api/cron/overdue-sweep` route + `vercel.json` schedule (daily 09:00 UTC). Cron auth via `CRON_SECRET`. **Walking skeleton.**
- **07-02: `overduePolicy.ts` pure function + unit tests.** Decision function `decideOverdueAction(task, today)` → returns one of `nudge_teammate | escalate_to_owner | auto_reschedule | none`. Cool-down logic. 100% unit-test coverage with fixture dates. No I/O, no LLM. Pure function.
- **07-03: Side effects — email + storage + log.** Resend templates (assignee nudge, owner escalate, auto-reschedule notice). `markOverdueAction(taskId, tier)` writes `overdue_tier`, `last_overdue_action_at`, event log row, and triggers email via existing Resend helper. Auto-reschedule path calls `buildSchedulePlan` → `setTaskSchedule` → log event. Snooze API + handler.
- **07-04: UI + owner controls.** Red "overdue" chip on `/tasks` cards + calendar cards (`/projects/[id]/tasks` calendar view). Owner-board tier-2/3 badges. Owner-only "Snooze N days" + "Force reassign" actions on task detail. Logger counters (`overdue.nudged | overdue.escalated | overdue.auto_rescheduled | overdue.snoozed`).
