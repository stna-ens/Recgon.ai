# Phase 3.6 Plan 02: Pure Overdue Policy Summary

**Decision function `decideOverdueAction(task, today) → OverdueAction` lands as a pure module with 41 vitest cases and 100% line coverage. Zero I/O. Plan 03 wires the side effects on top.**

## What shipped

1. **`src/lib/recgon/overduePolicy.ts`** (~165 lines):
   - `ACTIVE_OVERDUE_STATUSES` — canonical readonly tuple (`assigned | accepted | in_progress | awaiting_review`).
   - `daysOverdue(scheduledEndKey, today)` — integer day-delta on YYYY-MM-DD keys, UTC-midnight-anchored.
   - `decideOverdueAction(input)` — short-circuit decision tree (8 gates, in order: assigned → active status → has scheduled_date → feature flag → overdue > 0 → cool-down → tier band → no-skip clamp).
   - `isOverdue(task, today)` — UI helper for Plan 04's red chip + owner badges.
   - **No `new Date()` or `Date.now()` in source** — every clock value flows in via `today: Date`.

2. **`src/__tests__/overduePolicy.test.ts`** (~265 lines, 41 cases):
   - Full coverage of all 4 outcomes (`nudge_teammate` / `escalate_to_owner` / `auto_reschedule` / `none`).
   - All 6 short-circuit gates (unassigned, terminal status × 5, no scheduled_date, feature flag off, due today, due in future).
   - All band boundaries (1d / 2d / 3d / 5d / 6d / 7d / 30d).
   - No-skip clamp at tier 0 → tier 1 (even at 8 days), tier 1 → tier 2 (even at 7 days), tier 2 → tier 3.
   - 24h cool-down: 1h ago (blocked), 23h59m ago (blocked), 25h ago (fires), malformed timestamp (fails open).
   - Multi-day tasks (overdue measured from `scheduledUntilDate`, not `scheduledDate`).
   - All four active statuses fire when overdue.
   - `isOverdue()` UI helper — 6 cases covering each gate.

3. **`architecture.md`** updated with:
   - New file-table row for `lib/recgon/overduePolicy.ts` (decision tree, bands, exports).
   - Cron route row updated: "Plan 02 (landed)" with the policy file reference.

4. **`@vitest/coverage-v8`** added as a devDep so the ≥95% gate can be enforced going forward. `coverage/` added to `.gitignore`.

## Plain-English summary

Plan 01 built the plumbing (schema columns, cron route, type scaffolding). Plan 02 is the *brain* — but it doesn't do anything yet. It's a pure function that, given a task and today's date, returns "send a nudge to the teammate" or "send an escalation to the owner" or "auto-reschedule it" or "do nothing." No emails. No database writes. No LLM calls. Just one decision. Plan 03 will pick up that decision and turn it into an actual email + database write.

The reason this is its own plan: now we can change the policy (move the 3-day boundary to 4 days, lengthen the cool-down to 48h, etc.) and the tests catch regressions instantly without us ever sending a real email or touching real data.

- **None on logic.** Decision tree shipped exactly as the plan specified.
- **Test count over-shoots the plan minimum.** Plan asked for ≥15 cases; shipped 41. Coverage of branches + `isOverdue` helper drove it up — kept all of them because they're cheap (3ms total runtime).
- **Added `@vitest/coverage-v8` devDep.** Plan said "use `npx vitest run --coverage`" — but it failed with `MISSING DEPENDENCY @vitest/coverage-v8`. Installed it as a devDep so future runs work without surprise. `.gitignore` updated to ignore the `coverage/` output dir vitest writes there.
