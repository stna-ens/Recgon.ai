## Phase Goal (plain English)

Build the **brain** that decides what to do when a task is overdue — but only as a pure function. Pass in a task and today's date, get back one of `nudge` / `escalate` / `reschedule` / `nothing`. No emails, no database writes, no side effects. Pure logic + tests means we can iterate on the policy without fearing production. Plan 03 will wire the side effects on top.

Purpose: separate "what should happen" from "make it happen" so Plan 03 can wire effects with confidence, and so the policy itself is auditable + testable.

Function signature:

```typescript
import type { AgentTask, OverdueAction } from './types';

export const ACTIVE_OVERDUE_STATUSES = [
  'assigned', 'accepted', 'in_progress', 'awaiting_review',
] as const;

export type OverdueDecisionInput = {
  task: Pick<AgentTask, 'id' | 'status' | 'scheduledDate' | 'scheduledUntilDate'
    | 'overdueTier' | 'lastOverdueActionAt' | 'assignedTo'>;
  teamOverduePressureEnabled: boolean;
  today: Date; // local-time-anchored; the cron should pass new Date()
};

export function decideOverdueAction(input: OverdueDecisionInput): OverdueAction;

export function daysOverdue(scheduledEndKey: string, today: Date): number;
```

Decision tree (in order):
1. If `task.assignedTo` is null → `none` (unassigned tasks aren't overdue, they're a different problem).
2. If `task.status` not in `ACTIVE_OVERDUE_STATUSES` → `none`.
3. If `task.scheduledDate` is null → `none` (legacy backfill territory).
4. If `teamOverduePressureEnabled` is false → `none`.
5. Compute `overdue = daysOverdue(scheduledUntilDate ?? scheduledDate, today)`. If `overdue <= 0` → `none` (not yet overdue or due today).
6. If `lastOverdueActionAt` is within the last 24h → `none` (cool-down).
7. Compute next tier:
   - `overdue` in [1, 2] → next tier 1.
   - `overdue` in [3, 6] → next tier 2.
   - `overdue >= 7` → next tier 3.
8. If next tier > `task.overdueTier + 1` → cap at `task.overdueTier + 1` (no-skip rule). For a task at tier 0 that suddenly hits 8 days overdue (e.g. weekend cron skip), still emit tier 1 first; the next sweep moves it to 2; the one after to 3.
9. Map tier → action kind.

`daysOverdue` is a pure integer-math helper: parses YYYY-MM-DD, anchors today via `localDateKey(today)`, returns `today_key_as_int - scheduled_end_key_as_int` in days.

Test coverage required:
- Not assigned → none
- Each terminal status → none
- No scheduled_date → none
- Feature flag off → none
- Due today (overdue=0) → none
- 1 day overdue, tier 0 → nudge (tier 1)
- 2 days overdue, tier 0 → nudge (tier 1)
- 3 days overdue, tier 0 → nudge (tier 1, no-skip)
- 3 days overdue, tier 1 → escalate (tier 2)
- 5 days overdue, tier 1 → escalate (tier 2)
- 7 days overdue, tier 0 → nudge (tier 1, no-skip)
- 7 days overdue, tier 2 → auto_reschedule (tier 3)
- 1 day overdue, cool-down active (action 1h ago) → none
- 1 day overdue, cool-down expired (action 25h ago) → nudge
- Multi-day task — overdue measured from `scheduledUntilDate`, not `scheduledDate`.
