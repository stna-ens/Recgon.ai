<objective>
Wire viewer-discriminated reads end-to-end: the task detail API serves the personalized description ONLY to the assignee whose userId matches the row's `personalized_description_for_user_id`; everyone else (including the owner) sees the original brain description. The Resend assignment email applies the same rule.

Purpose: Plan 01 wrote the column; this plan makes it visible. Without this plan, the personalized description sits unused in the DB. After this plan, the assignee's experience is materially different from the owner's — the core UX promise of Phase 4.

Output: Updated API route, updated email body builder, updated TaskDetailPanel (consumes single description field — no client logic), two new test files.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
