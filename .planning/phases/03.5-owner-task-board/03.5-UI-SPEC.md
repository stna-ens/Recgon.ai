# Phase 3.5 — Owner Task Board · UI-SPEC

This SPEC locks the visual + interaction contract for the Owner Task Board.
Anchors: existing `src/components/v2/calendar/*`, design tokens in
`src/app/globals.css`, project memory `feedback_design_system_constraint`.

**Hard inheritance rule:** every new surface in this phase reuses existing
tokens (`--signature`, `--success`, `--warning`, `--rule`, `--bg-card`,
`--txt-pure/muted/faint`), existing classes (`glass-card`, `recgon-label`,
`cal-*` family from SwimLane/EventChip/WeekCalendar), JetBrains Mono for
labels + monospace data, and Radix UI primitives for any popover / menu /
dialog / tooltip. **No new aesthetic axis.**

---

## 3. Color Contract

**60% surface / 30% structure / 10% accent.** Inherited literally from
existing tokens. Light mode `--signature` = `#c2357a`. Dark mode = `#f0b8d0`.
Never use `#e8a8c4` (the pastel — banned per `feedback_signature_pink_lightmode`).

| Role | Token | Value (light) | Value (dark) | Reserved for |
|------|-------|---------------|--------------|--------------|
| Page surface (60%) | `--bg-canvas` (inherited) | white-ish | black-ish | Page background |
| Card surface (30%) | `--bg-card` | translucent white | translucent black | Grid frame, dock card, panel |
| Rule line | `--rule` | rgba subtle | rgba subtle | All cell borders, dividers |
| Body text | `--txt-pure` | #1d1d1f | #ffffff | Chip titles, headings, primary copy |
| Secondary text | `--txt-muted` | #86868b | #8e8e93 | Reason copy, secondary metadata |
| Faint text | `--txt-faint` | #a1a1a6 | #636366 | Hours, eyebrows, day number |
| **Accent (10%) — `--signature`** | `--signature` | `#c2357a` | `#f0b8d0` | **See reserved-for list below** |
| Success | `--success` | #34C759 | #30D158 | Capacity bar (healthy <60%), `completed/done/verified` chip accent |
| Warning | `--warning` | #FF9F0A | #FFD60A | Capacity bar (yellow 60-85%), `awaiting_review` chip accent, "PROOF NEEDED" eyebrow, unscheduled count badge |

### `--signature` reserved-for list (10% rule — DO NOT spend pink elsewhere)

1. **Eyebrow labels** (`PROJECTS`, `WHY YOU`, `WORKLOAD`, `TRIAGE`).
2. **Today's date** (border + color on `cal-day-header.is-today`).
3. **Active view-mode dot** (the `cal-view-trigger-dot`).
4. **Drop-target glow** during drag (`cal-day-cell.is-drop-hover`).
5. **Capacity bar fill at "red" overload** — the bar's "overloaded" state
   already glows pink in `cal-day-load-bar` (matches existing `SwimLane`
   load-bar treatment); we keep that.
6. **Triage-dock action button** ("assign manually") — signature accent
   on hover/focus only, neutral at rest.
7. **In-flight chip accent** (`in_progress` / `accepted` task status) —
   already wired in `EventChip.STATUS_COLOR`.
8. **"Moved by AI" badge border** on deferred chips — `rgba(--signature-rgb, 0.28)` border, signature text. Reuses `cal-chip-request` styling exactly.
9. **`whyYouSentence` eyebrow** in TaskDetailPanel.
10. **Dock collapsed-state pulse** (a faint signature glow on the
    "0 needs your eyes" header chip — purely decorative).

**Capacity bar 3-tier rule (D-07):**

| Utilization | Bar fill | Text color | Anchor |
|-------------|----------|------------|--------|
| < 60% (healthy) | `--success` (`#34C759` / `#30D158`) | `--txt-pure` | NEW class: `.capacity-bar.is-healthy` |
| 60-85% (approaching) | `--warning` (`#FF9F0A` / `#FFD60A`) | `--txt-pure` | NEW class: `.capacity-bar.is-warn` |
| > 85% (overload) | `--signature` with glow | `--txt-pure` | Reuse `.cal-day-load.is-overloaded` styling exactly |

We deliberately use signature pink (not red `var(--destructive)`) for
overload because Recgon's design system has no red — `feedback_design_system_constraint`
forbids alien aesthetics. Pink-with-glow already reads as "alarm" in the
existing daily load bar (`SwimLane.tsx` lines 269-275, 423-427).

### Workload grid (D-05, D-06)

- Reuses `WeekCalendar.tsx` grid mechanics 1:1 — same CSS grid template
  (`var(--cal-label-width) repeat(N, minmax(var(--cal-day-min-width), 1fr))`).
- **Column count = 14** (default 2-week window per D-06). Existing
  WeekCalendar uses 7; we extend by rendering `dayDates: Date[]` of length
  14. WeekHeader renders all 14 day cells. SwimLane already iterates
  `dayDates.map`, so 14 cells fall out for free.
- **Sticky teammate column** (`--cal-label-width` 180px) — already sticky
  via `position: sticky; left: 0;` on `.cal-lane-label`. Inherited.
- **Sticky day header** — already sticky via `position: sticky; top: 0;`
  on `.cal-day-header` and `.cal-corner`. Inherited.
- **Horizontal scroll** for 14-col window on narrower viewports — already
  handled by `.week-cal-scroll { overflow: auto }`. Inherited.
- **Outer frame** = the existing `.week-cal-outer` 28px-radius squircle
  with `glass-card`-style `backdrop-filter`. Do NOT stack a second
  `glass-card` inside (per `feedback_glass_treatment`). The SwimLane
  cells are already rendered inside the squircle.

### Triage dock (D-10, D-11)

```
EXPANDED (count > 0):
┌───────────────────────────────────────────────────────┐
│ ▼ TRIAGE  ·  4 NEEDS YOUR EYES                        │  ← header bar (eyebrow style)
├───────────────────────────────────────────────────────┤
│  Refactor auth module                                  │  ← row 1 — task title (mono 11px)
│  no clear fit                                          │     reason (system stack 12px italic)
│  [assign manually]                                     │     action button (mono 10px UPPER)
├───────────────────────────────────────────────────────┤
│  ... up to ~4 rows visible without scroll              │
└───────────────────────────────────────────────────────┘

COLLAPSED (count == 0):
┌───────────────────────────────────────────────────────┐
│ ▰  TRIAGE  ·  CLEAR                                   │  ← 40px tall pill, faint signature glow
└───────────────────────────────────────────────────────┘
```

- Card shell = `glass-card` class **inherited** (do not nest a second one).
- Header row uses the same eyebrow treatment as `cal-nav-eyebrow`
  (signature pink, 10px JetBrains Mono, 1.6px letter-spacing).
- Each task row is a 3-line stack: **title** (mono, pure), **reason**
  (system stack, muted, italic), **action** (mono pill button).
- Layout mode: vertical flex with 8px gap. NOT a grid — keeps it simple
  for variable-length reason copy.
- "Dismiss" `×` button (D-17) appears on the LEFT of the action button,
  ONLY for deferred items. Treat it as a Radix `Tooltip` trigger
  (tooltip text: "Dismiss from dock — task stays in calendar").
- Collapsed-state pill = same height as a `cal-view-trigger` button (~30px),
  centered horizontally, with a single faint signature glow on hover.

### Per-teammate capacity bar (D-07)

- Lives in the **lane label cell** (the sticky 180px left column), under
  the teammate name + title. Renders ABOVE any chips, INSIDE the lane row.
- Width: 100% of the lane-label cell minus 28px horizontal padding.
- Height: 16px — exact match to `cal-day-load` so the visual rhythm is
  consistent with the per-day load bars already rendered in cells.
- Shape: full-width pill with `border-radius: 8px`, dark inset, fill bar
  on the left.
- Per-week scope: shows utilization for the **week the lane is currently
  scrolled to**. With a 14-day window, render TWO bars stacked vertically:
  "Wk of May 16" (8h / 30h) and "Wk of May 23" (24h / 30h), each 16px tall
  with 4px gap between. Use the eyebrow ABOVE each bar (`WK 1` / `WK 2`,
  9px mono, faint, 1.2px letter-spacing).
- Hover (Radix `Tooltip`): shows breakdown — "8 of 30 hours scheduled · 5
  tasks across 4 days". Placement: `right`, 8px offset.

### View toggle (D-08)

- Reuse `cal-view-trigger` exactly. Options: `workload` (default) and `table`.
- Built on Radix `DropdownMenu`. Min-width 132px (matches existing).
- Active option marked with `•` glyph in signature pink (already implemented
  in `WeekNav.tsx` lines 113-118).
- **Table view** is a sortable table — see "Table view" section below.

### Table view (D-08, secondary)

```
┌─────────┬──────────┬──────────┬──────────┬──────────┬───────┐
│ TASK ↓  │ ASSIGNEE │ PROJECT  │ DATE     │ PRIORITY │ STATE │
├─────────┼──────────┼──────────┼──────────┼──────────┼───────┤
│ Wire... │ ens.kis  │ Recgon   │ May 17   │ high     │ assgn │
└─────────┴──────────┴──────────┴──────────┴──────────┴───────┘
```

- All-mono table inside a 28px-radius card matching `.week-cal-outer`.
- Header cells: 10px mono UPPER, faint, with `↑` / `↓` glyphs for the
  sorted column.
- Row height 44px (touch target floor + reading rhythm).
- Click any row → opens the same `TaskDetailPanel` as a chip click.
- No drag-drop in table view (drag is workload-only). Manual assign and
  reschedule menus are accessed via a kebab `⋯` button per row, opening
  a Radix `DropdownMenu`.

### Destructive actions

This phase has **one destructive-ish surface**: dragging a chip to
reassign in front of an assignee who already accepted it. Protocol:

- **No confirm dialog by default** — drag is an owner override, optimistic
  UI commits immediately, error reverts (inherits the existing
  `WeekCalendar.handleTaskDrop` pattern).
- **EXCEPTION:** if the chip is in `accepted` or `in_progress` state,
  open a `ConfirmDialog` first: title `Reassign in-flight task?`, body
  `{teammate} has already started this task. Reassigning will move it to
  {newTeammate} and cancel their work in progress.`, primary `reassign`,
  secondary `cancel`.

## 9. Privacy + Accessibility

### Privacy filter on `whyYouSentence` (Phase 3 contract — inherited)

- **Server boundary** (already enforced in `/api/recgon/tasks/[id]`):
  the response returns `whyYouSentence` only when the viewer is the
  task's assignee OR the team owner.
- **Client behavior:** because owner sees ALL teammates' chips,
  hovering / clicking any chip in the workload grid opens
  `TaskDetailPanel` with a populated `whyYouSentence`. This is by design
  (D-domain bullet 4 — owner needs to evaluate the AI's reasoning).
- **Members on the fallback view** never see the workload grid, so this
  privacy concern doesn't surface in this phase.
- **Hover preview on chips** (without click) does NOT show `whyYouSentence`
  — only chip title + hours (already the case in `EventChip` `title`
  attribute). Click is the gesture that opens the detail panel.

### Accessibility floor

- All interactive elements: visible focus ring (signature outline, 2px,
  2px offset — pattern already established in `cal-chip:focus-visible`,
  `cal-panel-btn:focus-visible`, `cal-nav-arrow:focus-visible`).
- Triage dock rows: `role="listitem"` inside `role="list"`. Action button
  has `aria-label` describing the task ("assign Refactor auth module").
- Workload grid: existing `SwimLane` chips already have `role="button"`
  + `tabIndex={0}` + Enter/Space keyboard handler. No regression.
- Capacity bar: `role="progressbar"` with `aria-valuenow`, `aria-valuemin=0`,
  `aria-valuemax={capacityHours}`, `aria-label="ens.kis week 1 utilization"`.
- Drag-and-drop keyboard: dnd-kit's `KeyboardSensor` enabled — Tab to chip,
  Space to grab, Arrow keys to move, Space to drop, Escape to cancel.
  Announces moves via dnd-kit's built-in `screenReaderInstructions`.
- Color contrast: all body text ≥ 4.5:1 against surface (existing tokens
  already satisfy WCAG AA in both light and dark modes — no regression).
