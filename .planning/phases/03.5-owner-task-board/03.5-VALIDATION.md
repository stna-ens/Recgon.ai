## Manual-Only Verifications

> Drag-drop UX, accessibility, and capacity-bar visual states require human eyes. Playwright deferred (manual UAT covers it for v1).

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| Drag chip from teammate A → teammate B reassigns successfully | SUCCESS-2 | Visual drop affordance + animation timing not testable in jsdom | Open `/projects` as owner. Drag any chip onto a different teammate row. Verify chip moves, success toast appears, refresh shows persisted assignment. |
| Drag chip from day X → day Y reschedules | SUCCESS-2 | Same as above | Drag chip onto different day cell. Verify chip moves, persists across refresh. |
| Drag chip from triage dock → calendar cell does both reassign + reschedule | D-18 | Combined operation needs visual confirmation | Drag dock row onto a teammate's day cell. Verify chip leaves dock, lands on cell, both fields persist. |
| Optimistic UI rollback on API failure | SUCCESS-2 | Network throttling + visual snap-back hard to assert in jsdom | DevTools → Network → throttle to "Offline". Drag a chip. Verify chip snaps back to original position + error toast appears. |
| Keyboard a11y for drag-drop | RESEARCH § a11y | Screen-reader cadence + focus ring not unit-testable | Tab to a chip, press Space, arrow-key to a target cell, Space to drop. Verify announcement + visual focus ring. |
| Member/viewer denial route | SUCCESS-5 | Role-based redirect must be visible | Log in as non-owner. Navigate to `/projects`. Verify project tiles render, NOT the workload board. |
| Touch-device fallback (list view) | RESEARCH § touch | Mobile gesture detection not in jsdom | Open in mobile viewport / phone. Verify falls back to today-tasks list + dock; no broken grid. |
| Capacity bar color transitions (green/yellow/signature) | UI-SPEC § Capacity | Threshold visual state requires real data | Manually mint enough tasks to push a teammate's week past 60% / 85%. Verify bar color shifts. |
