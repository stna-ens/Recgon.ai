## Deviations from Plan

### Rule 3 (blocking): ResizeObserver + IntersectionObserver shims

**Found during:** First test run of `tasks.personalHeaderStrip.test.tsx`.
**Issue:** The v2-tasks page light-tracking effect (lines 505-507) instantiates `new ResizeObserver(...)`. jsdom omits both `ResizeObserver` and `IntersectionObserver`. Mounting `V2TasksPage` in vitest threw immediately.
**Fix:** Top-of-file shim that polyfills both as empty-method no-op classes if absent. Matches the pattern from Wave 3's jsdom pointer-capture shim block.

### Rule 1 (bug-shaped design fix): TableBoard initial sort state

**Found during:** First green run of `ownerBoard.tableBoardSort.test.tsx`.
**Plan said:** "Initial sort: by `scheduledDate` ascending (null dates last)."
**Test expected:** Clicking DATE for the FIRST time produces asc-order rows.
**Conflict:** If initial state is `{ column: 'date', direction: 'asc' }`, then the first DATE click toggles to `desc` — contradicting the test.
**Resolution:** Internal `sort` state starts as `null`. The render-order fallback is `date asc` (so initial paint is never random per the plan), but no header glyph shows until the user has clicked. First click on any header sets `{ column, direction: 'asc' }`; subsequent same-column clicks toggle asc ↔ desc. This satisfies both the plan rule (initial paint = date asc) AND the test (first DATE click = asc).
**File:** `src/components/v2/projects/owner/TableBoard.tsx`.

### Rule 2 (correctness): TableAssignFlow overlay vs nested picker

**Found during:** Wiring kebab `assign manually` action into the table.
**Plan said:** "Per-row kebab `⋯` button opens Radix DropdownMenu with `assign manually` ... actions delegating to props."
**Reality:** Radix DropdownMenu closes synchronously on `onSelect`. Trying to render `AssignTeammatePicker` as a nested DropdownMenu.Sub or as a direct child of the menu item meant the menu would unmount before the picker had any time to mount.
**Resolution:** TableBoard's `onAssign(task)` callback sets a `tableAssignTask` state on the parent. `OwnerWorkloadBoard` renders a modal-style overlay (`TableAssignFlow`) keyed off that state. Selecting a teammate calls the existing `handleAssign(taskId, teammateId)` mutation path (same one used by the dock picker), so no new endpoint and no new optimistic logic.
**Files:** `src/app/projects/OwnerWorkloadBoard.tsx` (overlay component + state + render branch).

## Threat Model Status

- **T-3.5-01 (Authorization, view toggle):** mitigated. View toggle is rendered inside `OwnerWorkloadBoard`, which only mounts when role===owner (Wave 1 role router). Non-owners see `NonOwnerProjectsView` and never reach this component.
- **T-3.5-02 (Authorization, kebab actions):** mitigated. Both kebab actions (assign manually + reschedule) delegate to Wave-3 mutation paths (`/api/recgon/tasks/[id]/assign`, `/api/teams/[id]/tasks/[taskId]/schedule`). Both endpoints already enforce owner-only via `verifyTeamAccess`. No new endpoint introduced.
- **T-3.5-03 (Privacy, table row data):** mitigated. TableBoard consumes `gridTasks` from `OwnerWorkloadBoard` — same task list as `OwnerWorkloadGrid`, sourced from the bulk owner-board GET which strips `assignment_reasoning` per 03.5-02 Pitfall 3. Row click opens TaskDetailPanel via the existing per-chip route which applies the whyYouSentence privacy filter.
- **T-3.5-04 (Concurrency):** accepted as last-write-wins per CONTEXT. View toggle does not introduce new concurrency risk — mode-switching mid-drag is impossible (DragOverlay locks pointer state). Optimistic overrides survive the toggle because they live on the parent.

## Notes for Phase Verifier

1. **Owner-board endpoint mints `assignment_reasoning`-stripped rows:** unchanged from Wave 2. TableBoard consumes the same `gridTasks` slice that OwnerWorkloadGrid consumes — privacy filter inherited.
2. **Optimistic state survives view toggle:** `optimisticOverrides` is a `useState` on `OwnerWorkloadBoard`. Both workload-grid and table-board are children of the same component instance. Switching `viewMode` does not unmount the parent, so the override map persists. Manual UAT verification: drag a chip (optimistic), toggle to table, toggle back — chip is in the optimistic position.
3. **TableAssignFlow click-outside behavior:** the overlay's outer `<div>` has `onClick={onClose}` and the inner card has `onClick={(e) => e.stopPropagation()}`. Click outside the card → close. Click on the card → no-op. Click a teammate row → fire `handlePick` then close via `setTableAssignTask(null)`.
4. **TableBoard date-column DESC ordering with nulls:** test 2 expects `['Z urgent fix' (2026-05-19), 'A high task' (2026-05-17), 'M low task' (null)]` after the second click. This means descending = ISO descending order with nulls still pinned last — not nulls first. Verified in `compareTasks` `case 'date'` block.
5. **Header strip BELOW v2-section-head, not above:** intentional. Above would push the kanban down on every visit. Below preserves page rhythm.
6. **No new endpoints, no new tables, no migrations.** Pure client-side. Safe to deploy without backend coordination.
7. **Lint:** there are 11 pre-existing lint errors in the project (storage.ts, settings page, etc.). None are in plan-touched files. The new files lint cleanly.
