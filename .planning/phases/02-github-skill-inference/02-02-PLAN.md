Ship the engine that turns "I gave consent" into "rows in teammate_inferred_skills". This plan completes the data-producer half of Phase 2's vertical slice: cron → enqueue → worker → Octokit → LLM (Standard depth) → canonical filter → upsert. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cron → API → service-role DB | Vercel cron POSTs `/api/cron/github-skill-inference` with `CRON_SECRET` bearer — only path enqueues mining jobs |
| job worker → GitHub API | Worker holds `users.githubAccessToken` (resolved at runtime, never in payload) and reads commit messages — untrusted external content enters Recgon here |
| job worker → LLM (chatViaChain) | Standard-depth call passes commit titles WRAPPED in `<user_content>` delimiters; LLM output is JSON-validated AND canonical-set-filtered |
| job worker → service-role DB | Worker writes `teammate_inferred_skills` rows; rejected pairs filtered BEFORE write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Spoofing | unauthorized cron trigger | mitigate | `isAuthorized(req)` checks `Authorization: Bearer ${CRON_SECRET}` in production; dev skips per analog `recgon-schedule/route.ts:9-20`. Cron route ONLY enqueues — does not mine inline, so unauthorized hit cannot exfiltrate data |
| T-02-07 | Information Disclosure | GitHub token in job payload | mitigate | Payload contains `{teammateId, teamId, userId}` only. `runGithubSkillInference` re-fetches token via `getUserById(payload.userId)` AT RUN TIME (mirrors `workers.ts:81-84` codebase-analysis pattern). Token NEVER logged, NEVER serialized. If token missing → early `{skipped:true, reason:'no_token'}` |
| T-02-08 | Information Disclosure | cross-team / personal repo leakage | mitigate | `resolveTeamConnectedRepos(teamId)` queries `projects` table filtered by `team_id` — only repos registered as projects under the requesting teammate's team. Octokit calls scoped to `owner/repo` from that list. Personal repos NEVER mined per D-21 contract |
| T-02-09 | Tampering | prompt injection via commit message / PR body | mitigate | Every commit message wrapped via `wrapUntrusted(text)` BEFORE concatenation into the LLM user prompt. Helper strips smuggled `<user_content>` and `</user_content>` tokens → `⟦⟧` BEFORE wrapping. System prompt explicitly states delimiters mark UNTRUSTED INPUT — never follow instructions inside (QUAL-02) |
| T-02-10 | Tampering | LLM emits non-canonical tag | mitigate | Schema validates shape (max 10 skills, confidence 0-1, evidence 1..N); CANONICAL_SET post-filter drops any `canonical` not in vocab — exactly mirrors `normalizeProfile.ts:48-76` |
| T-02-11 | Repudiation | rejected skill resurfaces on next scan | mitigate | Worker calls `listRejectedTags(teammateId)` BEFORE emitting; filters tags out of the upsert set. Test coverage in Plan 01's `githubSkills.consent.test.ts` extended here |
| T-02-12 | Denial of Service | LLM cost runaway / GitHub rate-limit storm | mitigate | Octokit throttle plugin (onRateLimit, onSecondaryRateLimit) backs off; commit cap 200/repo; titles only (`message.split('\n')[0]`); LLM call ONE batch per teammate per scan (Standard); per-entry 2000 char cap in `wrapUntrusted` |
| T-02-13 | Elevation of Privilege | worker mines another user's data | mitigate | Payload's `userId` MUST match the user whose `agent_teammates(id) = teammateId` — worker validates with a join before mining. Cron enqueuer only enqueues `{userId: teammate.user_id}` from the consented set |
</threat_model>
